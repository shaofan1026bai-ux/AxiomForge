# 测点历史批量查询

- 接口 ID：`xiaomai.query.point-history.v1`
- 状态：2026-11-06 航信目标测点、两小时及近7个日历日分段查询已验证。
- 方法／路径：`POST /api/GatewayMicro/Point/GetPointHistoryData`。原资料另列GET，但无完整请求；本项目只使用已验证的POST。
- 鉴权：[用户登录](../auth.md)获取的Bearer Token。
- 副作用：只读查询。

## 请求样例

```json
{
  "timeQuantum": {
    "startDate": "2026-11-05 00:00",
    "endDate": "2026-11-06 00:00"
  },
  "indicatorNoList": [],
  "pointIdList": ["wh171k_mspm03_totalpower", "nfdh9q_mscrk01_c21"],
  "interval": 2
}
```

`pointIdList`支持同一次查询功率和室外温度；`interval=2`的返回时间间隔实查为2分钟。其他粒度、最大跨度、聚合函数、限流及保存年限尚待确认，不由示例推测。

## 响应结构

业务成功信封为 `success=true`、数值 `code=200`，`data`是按测点组织的数组。每项包含 `pointId`、`deviceId`、`projectId`、`pointName`、`unit`、`cycle`、`decimalPlace`及`pointDataList`等字段。历史值结构为：

```json
[
  {"ts": "2026-11-05 00:00:00", "val": 188.9},
  {"ts": "2026-11-05 00:02:00", "val": null}
]
```

上段仅说明时间和值的结构，不是连续成功样本的完整复本。`originalMaxData`、`originalMinData`可能来自不同采样口径；专题自行按已查询点值计算摘要，不混入这些字段。

## 本项目的数据契约

- UI与CSV统一现场时区`Asia/Shanghai`，查询范围采用`[start,end)`，归一化时剔除结束边界及越界点。
- 首版固定2分钟、最长7天，按最长24小时连续切片，同一请求同时获取两点；每个完整日实查为720点，结束于23:58。切片边界需去重，任一分段失败则整次查询失败，不发布部分成功快照。
- 真实0保留；`null`、缺记录、非有限数值不填0。按统一时间网格对齐，不做插值、平滑或最近时间强行配对。
- 相同时间相同值去重；同时间冲突值必须标明冲突。返回顺序、最新更新时间、极端数值均不能替代测点身份和数据质量检查。
- 散点与相关性只使用同一时间两点均有效的配对；均值与温度范围分别按各自有效值计算。有效配对比例的分母是所查区间期望网格点数。
- HTTP／业务失败、单位或测点归属不符、异常结构不能转换成成功空数组；成功空数组则应明确显示无数据。

当前上游未提供充分的质量码与聚合说明，因此这些完整性检查不表示传感器值必然准确，也不支持直接推断节能空间或能耗积分。
